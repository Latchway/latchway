# Latchway server 1.1.7

This patch closes the production diagnostic gap where rejected Client API
requests could be retained only as a route and HTTP status.

- Emit one structured `Client API problem` event for every RFC 9457 problem
  response, with bounded request correlation, closed endpoint and failure stage,
  validated SDK/caller, canonical error code, status and retryability.
- Reduce dynamic feature/component paths to fixed endpoint categories and mark
  invalid runtime declarations as `unknown`.
- Keep raw paths, headers, bodies, credentials, DPoP proofs, identity tokens,
  provider evidence/errors, user/install identifiers and arbitrary dependency
  messages out of these events.
- Persist and log closed stage-specific retention failures so operators can
  identify the failed transaction, relation or component/audit phase without
  retaining raw PostgreSQL errors.
- Document a Caddy runtime-log filter that deletes the complete request-header
  map and masks client addresses before proxy warnings are encoded.

Regression coverage proves the exact problem classification and confirms that
dependency details, identity tokens, proofs, bodies and headers cannot appear in
the new events. The complete Go suite, static analysis and documentation checks
pass.

Client contract 1.1.0, wire 1/2/3, contract bundle 1.1.2 and schema 33 are
unchanged. No database migration, application-policy activation or SDK update is
required.

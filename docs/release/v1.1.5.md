# Latchway server 1.1.5

This patch adds safe operator failure logs for Google Play Integrity and Apple
App Attest. It includes all server 1.1.4 fixes without replacing that immutable
release or changing existing SDKs, client fields, verifier policy or quotas.

- Emit `Attestation verification failed` structured warnings with a closed reason,
  processing stage, provider/platform, application/environment/configuration IDs,
  client correlation ID and independently generated server request ID.
- Preserve App Attest verifier phases, and distinguish Google decode HTTP status
  categories and recognized invalid app-verdict categories for operators.
- Cover verifier construction, preflight, evidence verification and selected
  pre-verification payload/binding failures, including native/RN and direct
  App Attest component step-up.
- Never log raw errors, provider bodies, tokens, assertions, certificates,
  attestation evidence, identity claims, private keys or request bodies.

Logs are process telemetry, not an audit ledger or an accepted-attestation event.
They require warn-level logging or more verbose and are retained according to
the deployment's log driver/collector policy. Container-local logs can disappear
on replacement; export or collect them before replacing a container when needed.
Past failed verdicts cannot be recovered by upgrading. A fresh attempt is needed.

Client contract 1.1.0, wire 1/2/3, contract bundle 1.1.2 and schema 33 are unchanged.
No database migration or application-policy activation is required.

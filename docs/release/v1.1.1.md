# Server 1.1.1

Contract 1.1.0, wire 3 (wire 1/2 retained), database schema 31.

Fixes `internal_error` during developer-supplied identity verification after a
session was issued. The original database rule required identity verification
to precede issuance, which conflicted with renewing an existing account's
identity. Migration 31 replaces only that issuance-time constraint. Identity
must still expire after verification; identity-less legacy grants retain their
original issuance bound.

The gateway still verifies the current provider token and same durable account,
requires live refresh possession and fresh DPoP, and rejects retired/rotated
credentials and replay. The operation does not modify credential issuance or
expiry, extend attestation, rotate keys, create accounts, or reset quota. The
released 1.1.0 contract archive and SDK contract locks are unchanged.

## Upgrade and rollback

Use server 1.1.1 or newer for supplied identity with iOS 1.2.0, Android 1.1.0 and
React Native 1.2.0. Back up PostgreSQL and retain the encryption/signing
configuration and previous image digest. Stop the old gateway, run the new
image's normal migration command, then start the matching image and check
readiness reports schema 31. Migration 31 needs a brief table lock and changes
no stored data.

Migrations are forward-only and readiness requires an exact schema match. A
schema-30 binary, including server 1.1.0, is not an application-only rollback
target after migration 31. If rollback is necessary, restore the pre-migration
database backup with its compatible image and preserved encryption/signing
configuration. Do not edit the migration ledger or grant timestamps to force
an old binary to start. Do not restore the issuance-only check after successful
identity renewals: their timestamps legitimately follow issuance.

## Verification boundary

The regression advances the clock after grant issuance and exercises the
authenticated HTTP endpoint, preserved credential/attestation lifetime,
same-user recovery, invalid identities, replay, and unchanged quota state.
Migration checks cover the schema-30 upgrade and transactional rollback while
preserving unrelated constraints, indexes and triggers. Public image and VPS
receipts are recorded separately; no Android physical or extension acceptance
is inferred from this fix.

# Latchway server 1.1.4

This patch improves error diagnosis and recovery without a database migration,
new protocol version, configuration change, or new Problem fields/codes.

- Preserve safe request validation details instead of replacing invalid tool,
  schema or request errors with a generic message.
- Return nonretryable `request_invalid` for requests that cannot fit a fixed
  per-request or token-bucket capacity. Replenishable quota errors retain
  `quota_exceeded`, identify the metric/maximum and include known retry timing.
- Distinguish upstream request rejection, operator configuration errors and
  temporary unavailability. Preserve bounded upstream retry hints without
  exposing raw provider error text. Classification does not authorize refunds:
  existing conservative usage/settlement rules stay in force.
- Report transient environment/configuration lookup failures as service
  unavailability instead of revoking a still-live session.
- Explain selected App Attest environment/signing and Play Integrity
  certificate/version/device/licensing/testing failures using server-authored
  guidance. Expired Play evidence uses `attestation_stale`. No verifier policy
  or cryptographic check is relaxed.
- Terminate started failed responses abnormally instead of returning a clean
  EOF with incomplete output. No response replay or out-of-format JSON is
  appended. Recognize Chat error envelopes and Responses failure/incomplete
  terminal events; retain valid terminal usage for failed-attempt settlement.

Upgrade SDKs to preserve the complete existing diagnostic envelope across native,
React Native and framework boundaries. Show the safe message and request ID;
do not log tokens, raw attestation, requests or provider response bodies.
Partial streamed output is not a completed result, and should not be replayed
automatically even when an earlier HTTP status was 200.

Client contract 1.1.0, wire 1/2/3, contract bundle 1.1.2 and schema 33 are unchanged.
The image is published as `ghcr.io/latchway/latchway:1.1.4` for Linux amd64/arm64.
Local regression checks are not a new physical-device or live-provider proof.

# Latchway server 1.0.4

This patch enables bounded Chat Completions function tools under trusted input,
total-token and input-priced cost quotas. It fixes the pre-dispatch
`request_invalid` failure when LangChain `bindTools` adds function definitions
to an otherwise working text request.

## Changes

- Account for function definitions, expanded local parameter schemas, named
  text messages, text-only content parts, assistant calls and correlated results.
- Accept boolean `strict` and `parallel_tool_calls`, plus `auto`, `none`,
  `required` or an enabled named function as `tool_choice`.
- Require complete call/result exchanges with unique IDs. Historical calls may
  refer to functions no longer enabled for the next generation.
- Share bounded schema accounting with Responses; bind each proof to its exact
  protocol, physical-model profile and rewritten request bytes.
- Preserve server-selected models, output caps, per-user quotas, DPoP, identity,
  required attestation and reserve/execute/settle semantics. Tools execute in
  application code, not in the gateway.

This is a bounded local text/function profile, not unrestricted Chat API support.
It allows at most 128 tool definitions, 128 calls per assistant message, 4,096
combined framing units, schema depth 64 and 4 MiB of expanded schema accounting.
Recursive, remote, unresolved and scope-changing schema references, media,
hosted/custom tools, legacy `functions`, `response_format` and unknown fields
remain rejected under trusted preflight. Sampling/extra provider fields are not
added by this patch. Keep the model options shown in the integration guide.

## Image and upgrade

`ghcr.io/latchway/latchway:1.0.4` is published for Linux amd64 and arm64.
Moving aliases are `1.0`, `1` and `latest`; pin the image digest for deployment.
Use the same image for server and migrator. Contract 1.0.0, wire 2 and database
schema 29 are unchanged; no new migration or active configuration edit is needed.
Keep the database URL, encryption master key and public origin unchanged.

Upgrade the gateway before enabling Chat tools in clients. Existing released
SDKs work; this does not require a new React Native SDK. Rollback to 1.0.3
preserves ordinary text chat but again rejects quota-bound tool requests.
Do not disable quotas as a workaround.

## Verification boundary

The full Go suite and targeted race tests pass. The authenticated PostgreSQL
integration exercises JSON and streamed tool-call/result exchanges through the
real gateway, including input/output/total/cost reservation, provider usage
settlement and unused-reservation release. Negative tests cover schema limits,
unsafe references, incomplete/duplicate tool history and altered accounting
proofs. Tool fixtures are synthetic; these tests do not claim new Habitify
physical-device, live-provider, cloud-matrix or independent-review evidence.

# Latchway server 1.0.2

This patch supports the expanded Foundation Models adapter in **iOS SDK 1.1.0**.

## Changes

- Responses accepts bounded metadata, top-k, reasoning controls, and local
  reasoning history, alongside tools and guided output schemas.
- Hard input/total-token quotas can account local tool calls/results and schema
  expansion. The final gateway validator includes that schema allowance while
  retaining exact rewritten-body size/digest and physical-model bindings.
- Historical function calls remain valid when their tool is no longer enabled
  for new calls.
- A single optional `[DONE]` after canonical `response.completed` no longer
  turns a valid OpenRouter stream into failed/unknown usage. Missing completion,
  duplicate terminal data, and malformed streams still fail.

## Image and upgrade

```text
ghcr.io/latchway/latchway:1.0.2
```

Linux amd64 and arm64 are published together. Moving aliases `1.0`, `1`, and
`latest` identify this patch after publication. Pin the release digest for
reproducible deployments; use the same image for server and migrator.

- Contract 1.0.0 and wire protocols 1/2 remain unchanged.
- Database schema stays **29**; there is no new migration.
- Keep the existing database URL, encryption master key, and public origin.
- Existing Habitify application and environment configurations do not change.
- A Foundation Models feature must use `openai_responses`, an appropriate
  server-selected model, and a matching input-accounting profile for hard quotas.

Rolling back to 1.0.1 requires no database rollback, but the expanded Foundation
Models requests require 1.0.2 and will be rejected by the older gateway.

## Limits and verification

The text-byte accounting method still rejects remote/opaque state, encrypted
reasoning, and recursive or unresolved schema references that it cannot bound.
It does not claim trusted accounting for image attachments. The LatchwayChat
example requests reasoning effort `none` so its 100,000-total-token daily quota
can be enforced without discarding encrypted state or bypassing policy.

All Go package tests and trusted-input fuzzing pass. The iOS 27 simulator suite
passes 17 Foundation Models tests. On a real development iPhone, Firebase Auth,
App Attest, Secure Enclave DPoP, two-city weather tool use, four Responses calls,
and 11,200 settled tokens were verified against the compatible private
deployment; URLSession chat also passed. This does not claim new production
Apple, extension, Android, cloud-matrix, or load certification.

# Latchway server 1.0.1

This server-only patch adds an explicit any-build policy for Apple App Attest:

```json
"allowedBundleVersions": ["*"]
```

Use this value in server-owned environment configuration through the Admin API
or the Console configuration editor. It accepts any well-formed attested build
version without updating configuration for each release. Existing exact build
allowlists still work. Empty lists and a wildcard mixed with exact versions are
rejected. The guided wizard continues to collect exact build versions.

Bundle identity, certificate/root trust, signing environment, signature, replay,
and validation-category checks remain enforced. Android's existing unrestricted
version bounds are unchanged.

## Compatibility and upgrade

- Image: `ghcr.io/latchway/latchway:1.0.1`, for Linux amd64 and arm64.
- No SDK upgrade or client wire-format change is required.
- Frozen client contract 1.0.0 and wire protocols 1/2 are unchanged.
- Database schema remains 29; no new migration is included.
- Keep the existing database URL, encryption master key, and public origin.
- Update both migrator and server to the same published image digest.

Version 1.0.0 rejects the wildcard. Before rolling back to 1.0.0, activate an
exact build allowlist in every environment that uses `"*"`. A compatible 1.0.1
image can reuse the existing configuration without that change.

## Validation scope

Targeted attestation, configuration, and session tests, including race tests,
passed for the policy change. This patch does not claim new physical-device or
cloud-conformance evidence. A live provider diagnostic's one-token output-bound
failure remains recorded in the implementation status; this release does not
change provider output-limit enforcement or waive that diagnostic.

# Latchway server 1.2.0

This minor release ships the redesigned Admin console and the Admin API it
needs. Client contract 1.1.0, wire 1/2/3 and the SDKs are unchanged; no app or
SDK update is required.

## What's new

- **Redesigned console**: new navigation with the workspace in the URL, a
  stepped Setup wizard, an Overview with what needs attention, and a header
  count of it.
- **Administrator sign-in**: own password, sessions and organization
  switching; two-factor sign-in with an authenticator app and recovery codes;
  passkeys; OpenID Connect single sign-on; invitations by link or email (SMTP
  via `LATCHWAY_SMTP_*`, optional); per-application Admin and Operator roles;
  read-only role preview. ADRs 0040 to 0045.
- **Users and requests**: server-side filters, sorts, capped totals and
  installation signals; impact previews and batched user actions; request
  search by client request ID, totals and facets. ADRs 0046 and 0047.
- **Configuration drafts**: drafts stay editable until published, can be
  discarded, record who changed which paths, take a publish note, merge onto a
  newer live revision, and can start from another environment. ADR 0048.
- **Policies and simulation**: who a limit would stop, overrides by plan, plan
  share, current limit usage, failure simulation with the data plane's retry
  and fallback rules, batch simulation and saved scenarios. ADR 0049.
- **Operations**: five-minute health samples of the server self-check (kept 30
  days), per-connection health from recorded attempts, a self-test run list,
  and display-name renames. Nothing can be deleted. ADR 0050.
- **Analytics**: month to date with a straight-line month-end projection, cost,
  latency and failures by AI connection, errors by code, and a warning when
  usage is still settling. ADR 0051.

Each feature is negotiated by an optional server capability, so the console
labels what an older server can't do instead of failing.

## Fixes

- Environment lists include `active_revision_id`, which the contract declared
  but the server never sent; Overview and Settings showed every environment as
  unconfigured.
- A validated, never-activated draft can be edited again. The console validated
  after every save, so its second save returned 409.
- The embedded console requires Admin contract 1.1.0, matching 1.1.x servers;
  it previously stayed in read-only mode.
- Analytics pages no longer render blank when reloaded in the embedded console.

## Upgrading

- **Schema 42.** Migrations 34 to 42 are forward-only and touch only
  administrator tables, configuration revisions and the job queue. A 1.1.x
  server can't start on schema 42, so plan a drained transition: back up
  PostgreSQL, stop the old gateway, run the 1.2.0 migration, then start 1.2.0
  and confirm readiness reports schema 42. Rolling back means restoring the
  pre-upgrade backup with the 1.1.7 image.
- **Upgrade the CLI with the server.** 1.1.x CLIs reject the fields 1.2.0 adds
  to configuration revisions, the session check, and requests that recorded a
  platform or client request ID.
- **Run a worker** for health history; without one, System Health says no
  samples exist yet.
- **Console links**: Analytics moved to `/usage`, `/cost`, `/performance` and
  `/reliability`; `/latency`, `/errors` and `/attestation-failures` redirect.

Admin contract bundle edition 1.1.3 is released with this server. Validation:
the Go suite against PostgreSQL 16, contract validation and generated
references, the console's lint, typecheck, unit, Playwright, build and
reproducibility checks, and the live-stack first-run test all pass.

# Server 1.1.0

Contract 1.1.0, wire 3 (wire 1/2 retained), database schema 30.

- Native-owned sessions can be shared by Swift/Kotlin and React Native. Each
  native host requires an explicit `sharedNativeCallers` policy; existing
  standalone native/RN configurations are not silently combined.
- Caller attribution appears in Admin API, CLI and Console request views without
  creating a new quota owner. User/feature limits remain shared across devices
  and caller languages.
- `GET /.well-known/latchway` advertises `supplied_identity_v1` and
  `/client/v1/sessions/identity`. The new identity-verification operation takes
  `{refresh_token, identity: {provider, token}}` with a fresh RFC 9449 proof.
  Only a freshly authenticated token for the same durable account may renew
  identity freshness; revoked or expired possession never restores a session.
- ID-token updates do not rotate Latchway credentials/keys, extend attestation,
  create users/installations, or reset quota. Initial sign-in and attestation
  renewal retain the existing challenge/exchange flow.
- SDK integrations may supply tokens from their application's existing auth
  code with no Firebase dependency in the new library graph. Applications must
  provide fresh tokens and notify logout/account changes.

## Upgrade

Back up PostgreSQL and the deployment's encryption/signing configuration. Run
the image's normal migration service, then start the matching image. Existing
schema-30 preview deployments require no new migration for identity verification.
Schema-29 binaries are not rollback targets after migration 30; restore the
previous schema-30 image or use a verified pre-upgrade database restore. Preserve
existing attestation and quota policies; enabling a shared native host is an
explicit configuration change, not an automatic effect of installing this image.

## Verification boundary

Server unit, complete PostgreSQL integration and targeted race results are
recorded in the implementation ledger. Coordinated SDK package publication and
VPS rollout have separate receipts. This release does not claim new physical
Android/Play acceptance, extension certification, or cloud verification.
